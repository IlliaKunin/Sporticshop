# Sportikshop

Интернет-магазин оригинальной спортивной обуви и одежды: витрина на английском и литовском, корзина, оплата Stripe (карты, Apple Pay, Google Pay), админка на русском, база Postgres.

Стек: Next.js 16 · TypeScript · Postgres (Neon) · Stripe · сжатие фото sharp.

## Запуск на своём компьютере (без регистраций и денег)

Нужен Node.js 22+.

```bash
npm install
cp .env.example .env.local        # на Windows: copy .env.example .env.local
npm run admin:hash -- "ваш длинный пароль"   # скопируйте результат в ADMIN_PASSWORD_HASH
```

В `.env.local` заполните:
- `SESSION_SECRET` — случайная строка 32+ символа: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`
- `ADMIN_EMAIL` и `ADMIN_PASSWORD_HASH`
- `PAYMENTS_MODE=fake` (оплата-имитация, только для разработки), `STORAGE_DRIVER=local`

```bash
npm run db:seed    # тестовые товары (по желанию)
npm run dev        # откройте http://localhost:3000, админка: /admin
```

Локально база — файл в папке `.data` (PGlite). Это только для разработки.

## Запуск в интернете (бесплатно, кроме домена)

1. **База:** создайте проект на Neon (бесплатный план), скопируйте connection string в `DATABASE_URL`. Таблицы создаются автоматически при первом запуске.
2. **Хостинг:** нужен вариант, где коммерческое использование бесплатно. Vercel Hobby для магазина не подходит (только некоммерческое). Проверьте условия Netlify или Cloudflare перед выбором. Переменные окружения из `.env.example` задаются в панели хостинга, а не в файле.
3. **Фото:** создайте бакет в Cloudflare R2 (или другой S3-совместимый), включите публичный доступ, заполните `S3_*` и `STORAGE_DRIVER=s3`.
4. **Stripe:** создайте аккаунт, возьмите `STRIPE_SECRET_KEY`. В Developers → Webhooks добавьте адрес `https://ВАШ_ДОМЕН/api/stripe/webhook` и события `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`. Скопируйте Signing secret в `STRIPE_WEBHOOK_SECRET`. Сначала проверьте всё на тестовых ключах (`sk_test_…`) и тестовой карте 4242 4242 4242 4242.
5. Установите `PAYMENTS_MODE=stripe`, `SITE_URL=https://ВАШ_ДОМЕН`, задайте `CRON_SECRET` (24+ символа).
6. **Cron:** раз в 10 минут вызывайте `GET https://ВАШ_ДОМЕН/api/cron/cleanup` с заголовком `Authorization: Bearer <CRON_SECRET>` (подойдёт бесплатный cron-сервис). Он возвращает в продажу пары из неоплаченных заказов.
7. Включите Stripe Radar, 2FA на аккаунтах хостинга, Stripe, Neon и GitHub.

Если конфигурация небезопасна (слабый секрет, `fake`-оплата, http), сайт в production откажется стартовать и напишет почему.

## Что защищено

| Угроза | Как закрыто |
|---|---|
| Подбор пароля админки | Лимит 5 попыток на 15 минут (email+IP), 30 в час на IP; одинаковое сообщение об ошибке; пароль хранится только как scrypt-хеш |
| Кража сессии | Подписанный токен в httpOnly-cookie, SameSite=Strict, Secure в production, срок 8 часов |
| Доступ к админке без входа | Проверка в прокси и повторно в каждой странице и каждом действии |
| SQL-инъекции | Все запросы с параметрами, значения никогда не вставляются в текст SQL |
| XSS | React экранирует текст; CSP запрещает внешние скрипты, фреймы, объекты |
| CSRF | Проверка Origin на API, встроенная защита Server Actions, SameSite=Strict |
| Подмена цены | Цена и сумма считаются на сервере из базы, браузер присылает только id размеров |
| Двойная продажа пары | Атомарное списание остатка в транзакции (проверено: 6 одновременных покупателей, 1 успех) |
| Поддельное «платёж прошёл» | Подпись вебхука Stripe, сверка суммы и валюты, обработка события один раз |
| Вредоносные файлы вместо фото | Фото декодируется и перекодируется в WebP, метаданные удаляются, имя случайное, до 6 МБ |
| Данные карт | Не проходят через ваш сервер: оплата на странице Stripe |
| Перебор и спам | Лимиты на заказы и корзину, ограничение размера запросов |
| Утечка секретов | Все ключи только в переменных окружения, `.env*` в `.gitignore` |
| Уязвимые библиотеки | `npm audit`: 0 уязвимостей на момент сборки; запускайте раз в месяц |

## Что проверено, а что нет

Проверено автоматически: покупка от корзины до оплаты (в тестовом режиме), смена языка, админка (вход, блокировка после 5 ошибок, создание товара с фото, отправка заказа, выход), отказ на подделанную cookie, отказ на чужой Origin, вебхук Stripe с верной и неверной подписью, повтор события, неверная сумма, истёкшая сессия, 6 одновременных покупок одной пары, вредоносные файлы вместо фото, обход путей.

**Не проверено с реальными сервисами:** живые платежи Stripe, загрузка фото в R2/S3, Telegram-уведомления. Проверьте их на тестовых ключах до запуска.

**Ещё не сделано:** оплата Paysera (банковские переводы), письма покупателям, двухфакторный вход в админку, юридические страницы (политика конфиденциальности, условия продажи, возврат). Для продаж в ЕС они обязательны, подготовьте их до запуска.

## Структура

- `app/[lang]/…` витрина (EN/LT), `app/admin/…` админка, `app/api/…` оплата, вебхук, корзина, cron
- `lib/` база, защита, заказы, оплата, фото, переводы
- `proxy.ts` заголовки безопасности и защита `/admin`
- Доставка и тарифы: `lib/shipping.ts`; тексты: `lib/i18n.ts`
